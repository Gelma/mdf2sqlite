# Cobi (mdf2sqlite)

## Quick overview

- Cobi translates Microsoft SQLServer `.mdf` files to SQLITE3
- reading 'em in binary mode directly
- no need for Microsoft engine working or installed;
- it works on Linux, Windows, and macOS (Apple Silicon M-series & Intel)
- it opens binary files in **read-only**, no writes touch your data
- you have a dir with sample in `SQL_sample_DB/` to play with
- the code is generated by Gemini, but tested and checked on my data all by myself (I wanna be...🎶🎤🎵)

## Quickstart
```bash
git clone https://github.com/Gelma/mdf2sqlite.git
cd cobi
make
# or: cargo build
./target/debug/cobi SQL_sample_DB/
ls -l output_sqlite/
```

**Cobi** is a fast, standalone, cross-platform command-line utility written in **Rust** that directly reads Microsoft SQL Server primary database files (`.mdf`) at the raw binary page level and converts them into clean, self-contained **SQLite3** (`.sqlite3`) databases.

**No running SQL Server engine or Windows service is required.** Cobi parses the on-disk B-Trees, data pages, system catalogs, and allocation maps completely offline on both **Linux** and **Windows**.

> [!NOTE]
> A comprehensive, in-depth technical summary of the binary structures, page headers, sector protections, allocation mechanisms, and record formats of SQL Server (`.MDF`, `.NDF`, `.LDF`, `.BAK`) can be found in [**MDF-Format.md**](MDF-Format.md).

---

## Key Features

- **Zero Database Engine Dependency**: Parses `.mdf` files offline without needing `sqlservr.exe` or local/remote SQL Server services.
- **Single File or Batch Directory Migration**:
  - Point to a **single `.mdf` file** to convert just that database into an individual `.sqlite3` file.
  - Point to an **instance directory** to recursively discover all `.mdf` files and convert them in parallel while preserving the subdirectory tree structure.
- **Complete Schema & Data Extraction**:
  - **Tables & Schemas**: Automatic mapping of SQL Server types to optimal SQLite affinities (`INTEGER`, `REAL`, `TEXT`, `BLOB`, `NUMERIC`).
  - **Foreign Key Constraints**: Reconstructed from system catalogs (`sys.sysschobjs`, `sys.syssingleobjrefs`, `sys.sysmultiobjrefs`) including composite keys and `ON DELETE` / `ON UPDATE` actions.
  - **Clustered & Non-Clustered Indexes**: Automatically extracts indexes from `sys.sysidxstats` and `sys.siscols`, honoring `UNIQUE` flags, multi-column key ordering, and `ASC`/`DESC` directions.
  - **Heap & B-Tree Storage**: Traverses Clustered Index B-Trees, scans Heap IAM extent allocations, and handles Forwarded Records and Sparse Vectors.
  - **Out-of-Row LOBs & Row-Overflow**: Seamlessly reassembles chunked and tree-structured Large Objects (`VARCHAR(MAX)`, `NVARCHAR(MAX)`, `VARBINARY(MAX)`, `TEXT`, `NTEXT`, `IMAGE`, `XML`).
- **Encoding & UTF-8 Normalization**:
  - Automatically converts `UTF-16LE` strings and Windows Codepages (`Windows-1252`, `Windows-1250..1258`, etc., resolved from SQL Server `collation_id`) into valid **UTF-8**.
- **Concurrent-Friendly WAL Mode**:
  - Output SQLite databases are configured in **WAL (Write-Ahead Logging)** mode (`PRAGMA journal_mode = WAL; PRAGMA locking_mode = NORMAL;`).
  - Schemas and Foreign Keys are committed upfront, and data rows are committed in incremental batches (`50,000` rows) so concurrent processes can read and query the SQLite databases while migration is actively running.
- **High-Performance & Low Overhead**:
  - Zero-copy read-only memory mapping via `memmap2`.
  - Automatic sector **Torn Page Detection** repair (`0x0100`).
  - Multi-threaded batch conversion powered by `rayon`.

## Installation & Build

### Prerequisites
- **Rust Toolchain** (1.75+ recommended):
  ```bash
  curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh
  ```
- **Linux**: Standard build tools and SQLite development library (`gcc`, `make`, `libsqlite3-dev`).
- **Windows (Cross-compilation from Linux)**: `x86_64-w64-mingw32-gcc` and the `x86_64-pc-windows-gnu` Rust target.

### Build on Linux
```bash
git clone https://github.com/username/cobi.git
cd cobi
make release
```
The compiled binary will be placed at `target/release/cobi`.

To install to system binary and man page paths:
```bash
sudo make install
```

### Build for Windows (Standalone `.exe`)
Cobi compiles `sqlite3.c` statically for Windows targets via `build.rs`, generating a completely standalone PE32+ executable without requiring external runtime DLLs:
```bash
make windows
```
The resulting executable is generated at `target/x86_64-pc-windows-gnu/release/cobi.exe`.

### Build on macOS (Apple Silicon & Intel)
On macOS, SQLite3 is part of the system SDK (`/usr/lib/libsqlite3.dylib`). You can build natively with:
```bash
make release
```
Or target a specific Apple architecture:
```bash
# Apple Silicon (M1/M2/M3/M4)
make macos-arm64

# Intel Mac
make macos-x86_64
```

## Usage & Examples

### Command-Line Synopsis
```text
cobi <source_dir_or_mdf> [dest_dir_or_sqlite] [--jobs N] [--no-recursive] [--indexes-only]
```

### Options
| Option | Description |
| :--- | :--- |
| `<source_dir_or_mdf>` | Path to a single `.mdf` file or a directory containing `.mdf` databases. |
| `[dest_dir_or_sqlite]` | Destination path (output directory or `.sqlite3` file). Defaults to `./<name>.sqlite3` for a single file or `./output_sqlite` for a directory. |
| `-j, --jobs <N>` | Number of parallel worker threads (default: logical CPU count). |
| `--no-recursive` | When `<source>` is a directory, scans only the top level without entering subdirectories. |
| `--indexes-only` | Updates existing SQLite databases by only importing/rebuilding indexes and foreign keys. |
| `-h, --help` | Displays help information. |

---

### Examples

#### 1. Convert a Single SQL Server Database
Convert a specific `.mdf` file directly into a dedicated `.sqlite3` database:
```bash
./target/release/cobi SQL_sample_DB/TestImport.mdf /data/sqlite/TestImport.sqlite3
```

Convert a single file with default output naming (creates `TestImport.mdf` in the current directory):
```bash
./target/release/cobi SQL_sample_DB/TestImport.mdf
```

Convert a single file into a target directory:
```bash
./target/release/cobi SQL_sample_DB/TestImport.mdf ./output_sqlite/
```

#### 2. Convert an Entire SQL Server Instance Directory
Recursively discover and migrate all `.mdf` files across subdirectories into `./output_sqlite`, preserving directory hierarchies:
```bash
./target/release/cobi SQL_sample_DB/ ./output_sqlite
```

#### 3. Control Parallel Worker Threads
Limit execution to 4 concurrent worker threads on constrained environments:
```bash
./target/release/cobi SQL_sample_DB/ ./output_sqlite --jobs 4
```

#### 4. Import / Refresh Indexes Only
If you already converted tables and data and wish to extract and generate all Clustered and Non-Clustered indexes or Foreign Key constraints:
```bash
./target/release/cobi SQL_sample_DB/ ./output_sqlite --indexes-only
```

#### 5. Background Execution Scripts
Helper bash scripts are provided for headless/daemon runs:
```bash
# Start background conversion
./start.sh SQL_sample_DB/ ./output_sqlite

# Stop a running job gracefully
./stop.sh
```

## Architecture Overview

Cobi is organized into clean, layered modules:

| Module | Responsibility |
| :--- | :--- |
| **`page.rs`** | 8192-byte page engine, page headers, sector de-tornification, PFS allocation, IAM bitmaps, and B-Tree navigation. |
| **`record.rs`** | `PrimaryRecord`, `ForwardedRecord`, null bitmaps, variable-length offset arrays, complex columns, and sparse vectors. |
| **`lob.rs`** | Text pointers, Yukon inline blob roots, row-overflow pointers, and recursive chunk reassembly (`SMALL_ROOT`, `INTERNAL`, `DATA`, `LARGE_ROOT_YUKON`). |
| **`types.rs`** | SQL Server primitive and spatial type decoding, collation LCID resolution, and Windows codepage / UTF-16LE to UTF-8 transcoding. |
| **`catalog.rs`** | Bootstrapping system catalogs (`sys.sysallocunits`, `sys.sysrowsets`, `sys.sysrscols`, `sys.sysschobjs`, `sys.syscolpars`, `sys.sysidxstats`, `sys.siscols`, `sys.syssingleobjrefs`). |
| **`sqlite.rs`** | Direct SQLite C FFI integration, DDL generation with Foreign Keys, WAL configuration, batch inserts, and index generation. |
| **`main.rs`** | CLI parsing, single-file vs. recursive parallel directory traversal, progress reporting, and statistics aggregation. |

For an in-depth reference on the physical structures of SQL Server files, see [MDF-Format.md](MDF-Format.md).
